# formulario-pok-mon
Formulário de cadastro de treinador Pokémon desenvolvido em HTML<hr>
<b>GET vs. POST</b><br>
No método POST, os dados aparecem no corpo da requisição e não ficam visíveis diretamente na URL. Já no método GET, os dados são adicionados à URL depois do ?. Para este formulário, o método POST faz mais sentido, pois é mais adequado para enviar uma quantidade maior de informações e arquivos.<hr>

<b>Codificação</b><br>
Os caracteres especiais aparecem codificados, como o espaço sendo representado por %20 ou + e o @ por %40. Isso acontece porque a URL precisa usar uma forma padronizada de representar caracteres que possuem significado especial, garantindo que os dados sejam transmitidos corretamente.<hr>
<b>Reflexão</b><br>
1. Que tema você escolheu e por quê?

Escolhi o tema Pokémon porque é um tema que eu gosto muito e que fez parte da minha infância. Pude usar imagens de pokémon, relembrar regiões do anime e fazer um formulário para cadastrar treinadores. 

2. Por que você usou GET ou POST no seu formulário?

Usei o método POST porque ele envia os dados no corpo da requisição, sem deixar as informações aparecendo diretamente na URL. Para o meu formulário, achei mais adequado porque ele possui vários campos e também permite o envio de arquivo.

3. Cite um momento em que teve que decidir entre dois controles e explique sua escolha.

Tive que escolher entre select e radio para selecionar o Pokémon principal. Escolhi o radio porque o usuário deve escolher apenas um Pokémon, e assim consegue visualizar todas as opções diretamente na tela.

4. O que você faria diferente se tivesse mais tempo?

Se tivesse mais tempo, eu adicionaria mais Pokémon, melhoraria algumas partes do design e criaria uma área que mostrasse o perfil do treinador depois que o formulário fosse enviado. Também poderia deixar o formulário ainda mais interativo.
